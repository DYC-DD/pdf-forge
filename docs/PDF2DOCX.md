# PDF2docx 開發紀錄

05 PDF2docx 是獨立的開發預覽功能，網址為 `/pdf2docx/`。04 的 PDF 與圖片轉換維持原流程；待品質驗證完成，再決定是否整合。

## 原則

- PDF、擷取文字、頁面影像與 DOCX 都留在瀏覽器中。沒有上傳 API、遠端 OCR 或雲端語言模型。
- OCR worker、WASM 與繁中／英文模型由本站靜態檔案提供。首次需要下載程式與模型，不代表上傳文件；語言模型可能由瀏覽器快取，文件內容不寫入持久儲存。
- 正文使用 Word 原生段落，清單使用編號定義，表格使用原生儲存格。位置資訊用來推斷結構、縮排、間距與欄寬，不把每行文字放進獨立文字方塊。
- 字元數、來源片段覆蓋檢查與 OCR 信心值都是診斷資訊，不能代表內容正確率。開發預覽不承諾所有 PDF 都能完整還原。

## 第一階段已建立

1. 獨立入口、頁碼選取、原稿預覽、辨識設定、結構預覽與 DOCX 下載。
2. PDF.js 讀取文字、座標、字級及字型名稱；推斷粗體、斜體，重建文字行、段落、首行縮排與段距。
3. 偵測簡單雙欄及跨欄元素，重建 Word 分欄與欄寬。
4. 從水平／垂直線段重建至少 2 × 2 的有框線表格，支援矩形的水平與垂直合併儲存格。
5. 保留可分離的點陣圖片，正文維持可編輯。
6. 本機 Tesseract.js OCR：繁中＋英文或英文；自動處理純圖片、異常字元映射或包含可見表單值的頁面，也可手動整頁重新辨識。
7. 文件模型保存來源頁碼、文字片段識別碼與診斷資訊。無法涵蓋全部來源片段或無可輸出文字／圖片時阻止下載。
8. 分析與 DOCX 打包使用獨立 Worker，提供取消與逾時處理。OCR 模型載入途中取消後，尚未初始化完成的 Tesseract worker 會在完成初始化時釋放。
9. 自動讀取 PDF 實際尺寸與方向，優先匹配 A4、A3、A5、Letter（容許約 1% 或 3 pt 的尺寸誤差）；不吻合時保留原稿尺寸，不依長寬比強制猜成 A4。使用者不需設定紙張、方向或邊界。
10. 輸出時依實際紙張座標換算位置，保留原有留白、欄寬與字級；不再把每頁內容範圍拉伸至邊界。圖片只縮小、不放大，維持比例並限制於可用頁高。
11. 並排圖片使用單列無框線原生表格保留關係；簡單側邊圖片錨定於原生段落並使用 Word 圖文環繞。重疊圖片分片與相接的圖片磚先合併可見範圍，再以約 216 DPI 擷取，避免重複圖片和分片散落。
12. OCR 保留辨識器提供的區塊與段落識別，避免相近座標的不同內容被合併；短雙欄至少各兩行也會分析閱讀順序。整頁 OCR 後仍可保留未含辨識文字的獨立內嵌照片。

## 依多類原稿改善的物件架構

分析先把可見內容分配給物件，再建立閱讀順序與 Word 排版：

- **原生文字**：讀取字型、字級、色彩、水平縮放、字元前進距離與底線；修復部分 UTF-8 字型名稱。後繪製的不透明矩形完整遮住的舊範本文字不輸出；透明填色不據此刪字。每個可見文字片段只歸屬正文、表格、公式或頁尾其中一處。
- **字型度量**：先偵測裝置可用的楷體、明體與黑體替代字型，分開量測中西文字寬；在原生儲存格與 OCR 原稿行內校準水平字寬，保留原字級，禁止為填滿空白而拉寬文字。不可信或不可用的字型度量會退回原有處理。關閉 Word 的自動中西文間距，避免額外空白擠出換行；LibreOffice 對此設定的處理仍有差異。
- **表格**：向量線與掃描長線都交由同一個網格分析器，重建欄寬、列高、矩形合併儲存格、底色、框線與垂直對齊。薄填色矩形先轉成中心線；跨過實際欄界的文字片段，依字元寬度及空白間隙拆回儲存格。內距依原稿推估，表內保留來源換行與字寬，文字仍是可編輯的原生段落。小數不當作清單編號，靠右與置中對齊不再重複套用左縮排。
- **線條**：表格框線先由表格認領；貼近文字基線的底線改為文字樣式，其餘水平分隔線輸出為段落框線。裁切路徑不能當作填色矩形。
- **圖片與裝飾**：圖片單獨渲染，避免把附近文字一起烘焙進圖像。圖章、頁邊圖像與可判定的大型斜向浮水印可使用頁面錨定圖片；原生正文維持可編輯。Multiply 圖章，以及覆蓋數個文字片段、具大面積白底且色彩幾乎全為紅色的圖章，轉成透明背景；普通圖片保留原背景。這是保守的圖像啟發式，仍應核對原稿。
- **複雜圖片頁**：保留大型照片；交錯繪製的點陣圖與向量裝飾組成不含正文的圖像層，保留遮擋順序，正文仍是原生文字。這類圖像層採高品質 JPEG，透明圖章及獨立向量圖層保留 PNG。頁尾圖像另錨定在 Word 頁尾，避免白底遮住頁尾文字。
- **基本公式**：以分數線、上下置中文字及同基線運算符共同辨識簡單分數，輸出可編輯的 Word 公式；不把普通底線當成分數。只在可判定的配對位置修正部分數學字型的括號映射。複雜公式仍需核對。
- **頁面種類**：自動區分有文字層、需要 OCR 的整頁掃描與獨立圖片頁。留有頁邊的地圖等獨立圖片頁可直接保留，不強迫 OCR 成零碎文字。整頁重辨識仍可由使用者指定。
- **掃描幾何**：OCR 前偵測長表格線並移除辨識輸入中的線條，原檔保持不變；修正誤判成直排的清單標記，以常見字框群估算字級，限制表內無法容納的異常大字。以繁中模型優先辨識，英文主導頁面才用英文模型重試，避免兩種字元假設互相干擾；下一頁恢復主模型。以相鄰中文字距補助字級估算。保留原稿軟換行、定位點與封面留白；可確定的底部數字及重複原生頁尾文字使用 Word 頁尾，數字使用頁碼欄位。文字及網格遮罩後的大型殘餘圖形另保留像素，圖內文字明確標示仍屬圖片。
- **橫向 OCR 重試**：密集且有多行跨過頁寬一半的繁中正文，排除網格後，以橫向單區塊模式再辨識一次。同基線、間隙小於約一個字高的 OCR 行片段先合併判斷，避免標點附近被切段而漏掉重試；較寬的欄間距與分散的起點不作為整頁正文證據。結果必須保有文字量、足夠的文字相似度及不低於首輪的辨識信心才採用，完成後恢復自動模式。這可減少清單標記被當成直排漏字；網格、封面及稀疏表單不會啟用此重試。重疊字框的寬度改採實際範圍；同一行的細小標記不再增加獨立段落，定位點後不多加空白。數字頁尾移除多餘行距，保留字級與底部錨點。

## 管線與程式位置

```text
File / ArrayBuffer
  → PDF.js 文字、字型、繪圖路徑與圖片位置
  → 必要時以頁面影像執行本機 OCR
  → RawPage（文字片段、座標、線段、填色與圖片）
  → 物件分類／歸屬（正文、表格、底線、分隔線、圖片、浮水印、頁碼）
  → Layout Worker（行、段落、閱讀順序、分欄）
  → DocumentModel（頁面、段落、清單、表格與診斷）
  → Export Worker（docx / OOXML）
  → Blob / 本機下載
```

- `src/features/pdf2docx/lib/extractPage.ts`：PDF 內容讀取與圖片擷取。
- `lib/ocr.ts`、`lib/ocrGeometry.ts`、`lib/ocrLayout.ts`、`lib/scanRules.ts`、`lib/scanGraphics.ts`：本機模型、橫向重試選擇、掃描線條預處理、字框／基線修正與 OCR 生命週期。
- `lib/pageObjects.ts`：正文、表格、水平線、圖像及頁碼的歸屬分類。
- `lib/textAppearance.ts`、`lib/imageAppearance.ts`：原生字型／色彩及圖章透明背景。
- `lib/paragraphs.ts`、`lib/tables.ts`、`lib/fractions.ts`、`lib/layout.ts`：幾何、表格、簡單分數與結構推斷。
- `types.ts`：來源模型與可編輯文件模型。
- `lib/exportDocx.ts`：原生 Word 段落、編號、表格、圖片、分節與分欄。
- `lib/fontMetrics.ts`：可用替代字型偵測、中西文字寬量測與保留字級的水平校準。
- `lib/pageSetup.ts`：自動匹配常見紙張與方向，綜合同尺寸頁面的正文、表格、分欄及圖文環繞位置推估邊界，再映射輸出座標。
- `vite.config.ts`：從已安裝套件複製 OCR 靜態資源，支援 GitHub Pages base path；授權與來源說明一併輸出到 `ocr/`。

這是獨立的 TypeScript 初版實作，尚未逐項移植或達到 pdf2docx、Docling 的完整功能。沒有在瀏覽器中執行 Python 或 Pyodide。

## 現有限制

- 單檔 32 MB，來源最多 600 頁；每次選取最多 50 頁，其中 OCR 最多 10 頁。
- 單頁最多 25,000 個文字片段、100,000 個繪圖操作與 2,000 條表格候選線；保留圖片總量最多 32 MB。
- OCR 畫布最多 800 萬像素、單邊 4,096 像素。一般頁面以約 216 DPI 辨識，特殊尺寸會縮小。
- 每頁 OCR、版面 Worker 與輸出 Worker 各有 2 分鐘逾時限制；大型手機文件的實際效能仍需擴充驗證。
- 字型以可用字型替代，未嵌入原 PDF 字型；楷體／明體對應裝置上的字型。原生文字的 RGB 色彩可保留，掃描字型、粗體與色彩尚不能可靠還原。Word 與 LibreOffice 使用不同替代字型時仍可能重新換行。
- 一般直排／旋轉文字、RTL、複雜公式、無框線表格、三欄以上、完整頁首頁尾語意及複雜浮動圖形尚未完整重建。向量裝飾可依圖像保留，但不會變成可編輯的 Word 圖形。
- 單張整頁掃描影像可重建 OCR 文字及部分有線網格表格，大型低文字密度圖形可以保留，但圖文密集、淡色或破碎邊界仍可能分離不全；獨立內嵌圖片可保留。線條移除仍可能影響貼線字形，掃描中文字、數字與合併儲存格需要逐頁核對。
- 圖文環繞目前限於同一書寫區域中、頂端相近且左右不重疊的單張圖片與正文。多圖環繞、跨欄圖形與複雜遮罩仍需核對，Word 與 LibreOffice 的浮動圖形重排可能不同。
- 自動模式不會辨識每張局部圖片內的文字，相關頁面應核對，必要時使用整頁重新辨識。
- OCR 信心高仍可能辨識錯字、數字或全半形標點；不能把辨識信心顯示成正確率。

## 驗證與下一階段

新增回歸案例另涵蓋厚填色網格、字元跨欄拆分、不透明遮擋與透明填色、原生重複頁尾、基本分數／非公式底線、大型照片與向量合成、頁尾圖層隔離、掃描圖形／小殘餘字群及 OCR 語言切換。最新案例涵蓋字型可用性／中西文量測、保留字級的儲存格校準、重疊字框、細小同列標記、換行／定位點空白、厚框線高度、近底部表格留白及橫向 OCR 重試的選擇與還原。既有案例涵蓋小數與清單區分、對齊／縮排、填色與裁切路徑、紅字與底線、圖章透明背景、斜向浮水印隔離、圖片頁輸出、掃描網格、異常直排標記與頁尾欄位。

自動測試涵蓋跨行段落、繁中標點、樣式、清單、雙欄閱讀順序、不等欄寬、合併儲存格、原生圖片、橫式頁面、跨頁接續、文字覆蓋、可見表單值、取消、逾時與 Worker 錯誤。

紙張與圖片回歸測試另涵蓋自動辨識 A4／A3／A5／Letter／原稿尺寸及方向、窄／標準邊界推估、同紙張的跨頁共識、稀疏／空白頁、自訂尺寸與邊界、圖片比例與頁高限制、並排圖片、原生圖文環繞、圖片範圍裁切與分片合併、短雙欄及 OCR 段落分界。窄／標準邊界的並排與環繞範例均以 LibreOffice 渲染後檢查；這些合成案例不能替代使用者原稿與 Microsoft Word 的驗證。

實際 PDF 測試鎖定 PDF.js 6 的 packed DrawOPS 路徑格式；升級 PDF.js 時必須重新驗證。測試輸出的 DOCX 可用以下方式寫入暫存目錄，供 Word／LibreOffice 渲染與逐頁檢查：

```bash
PDF2DOCX_QA_DIR=/tmp/pdf2docx-qa npx vitest run src/tests/pdf2docx-*.test.ts
```

後續依下列順序推進，維持每階段可獨立驗證：

1. **建立品質基準**：收集取得授權的繁中／英文原始 DOCX、匯出 PDF 與掃描版本，人工標註正確文字、段落、閱讀順序與表格。量測 CER、數字／標點錯誤、結構正確率與編輯後流動行為。
2. **改善讀取與 OCR**：異常字元映射、混合掃描區域、傾斜／低對比預處理、疑字定位與原稿對照；以相同測試集比較其他可在 WASM／ONNX Runtime Web 執行的辨識模型。
3. **改善版面重建**：頁首頁尾、無框線表格、跨頁表格、清單層級、三欄以上、段落跨頁接續、字型度量與圖文繞排。
4. **正式品質驗證**：Word 與 LibreOffice 都檢查分頁、合併儲存格、缺字與編輯後重排；補齊主流瀏覽器、手機記憶體及斷線情境，再評估與 04 整合。

可持續參考 [pdf2docx](https://github.com/ArtifexSoftware/pdf2docx)、[PdfPig](https://github.com/UglyToad/PdfPig) 與 [Docling](https://github.com/docling-project/docling) 的結構推斷與文件模型；引入實際程式碼或新模型時，另行核對相應版本的授權與瀏覽器依賴。
