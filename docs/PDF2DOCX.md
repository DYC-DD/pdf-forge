# PDF 轉 Word（PDF2docx）

PDF2docx 是 PDF Forge「04 轉換 PDF」中的 Word 轉換功能，入口為 `/convert/`，輸出格式標示為 **Word beta**。舊 `/pdf2docx/` 連結會導向轉換工具。

此功能在瀏覽器中讀取 PDF，將可重建的文字、段落與表格轉成可編輯的 Word 內容，並以圖片保留圖像及難以可靠辨識的區塊，最後將所選頁面輸出為一份 DOCX。功能仍在開發與優化中，可編輯程度與版面還原效果會隨原稿內容而異。

## 使用流程

1. **加入 PDF**：在「04 轉換 PDF」加入一份文件，將輸出格式設為 Word beta。
2. **選擇頁面**：預設全選，可點選縮圖，或輸入頁碼範圍（例如 `1-3, 5, 8`）後套用。頁面清單支援全選、清除、列表與網格顯示。
3. **掃描文件內容**：讀取所選頁面的文字、表格與圖片，必要時自動執行 OCR。更換文件或變更選取頁面後，需重新掃描。
4. **下載 Word**：所選頁面依原稿順序輸出成一份 `.docx`，預設沿用原檔名，也可修改輸出檔名。

文件匯入、頁面選取與原稿預覽和 JPG／PNG 輸出共用。Word 轉換會自動決定辨識語言、紙張、邊界與分頁方式，無須額外設定。

掃描完成後，輸出區會顯示可編輯字元數、Word 表格數與需核對的頁數。保留在圖片中的文字不計入可編輯字元數。

未選取頁面時無法掃描；尚未完成掃描或有頁面讀取錯誤時無法下載。處理期間可取消，讀取失敗、逾時或資源超限時會顯示原因。

## 內容辨識與輸出策略

### 優先讀取原生文字

有可用文字層的 PDF 會直接讀取文字、座標、字型、字級、色彩與繪圖資訊，再推斷閱讀順序及文件結構。每個可見文字片段只歸屬正文、表格、公式或頁尾其中一處，避免重複輸出。

被後繪製的不透明矩形完整遮住的文字不會納入結果；透明填色不作為刪除文字的依據。正文使用 Word 原生段落，清單使用編號定義，表格使用原生儲存格。

### 必要時執行本機 OCR

整頁掃描、異常字元映射、無文字層的向量內容，或無法直接讀取的可見表單值，會自動進入辨識流程。留有頁邊的地圖等獨立圖片頁，可直接以圖片保留。

OCR 的主要處理包含：

- **辨識語言**：以繁體中文模型為主，英文主導的頁面視結果改用英文模型重試，後續頁面恢復主要模型。
- **掃描預處理**：校正傾斜、偵測表格線，修正字框、基線與異常字級。候選線條需有明亮底色作為佐證，減少照片紋理被誤判為框線；移除線條只作用於辨識輸入。
- **橫向正文重試**：密集繁中正文可另以單區塊模式辨識，只有文字量、相似度與辨識信心符合條件時才採用結果。
- **局部重辨識**：針對文字行與儲存格使用加白邊的裁圖及有限次去雜訊，逐字比較候選結果，保護已清楚讀取的數字。主要辨識保留原稿字形，避免處理浮水印時擦除正文。

### 以完整段落決定可編輯範圍

掃描頁先重建文字與表格，再依內容可靠程度分配可編輯內容與原稿影像：

| 內容狀況                                           | 輸出方式                               |
| -------------------------------------------------- | -------------------------------------- |
| 系統判定能可靠重建的正文                           | 可編輯的 Word 段落與清單               |
| 網格與文字均能可靠重建的表格                       | 原生 Word 表格                         |
| 段落內有浮水印重疊、低信心內容或易受底線干擾的數字 | 整段保留原稿裁圖                       |
| 儲存格重辨識後仍有明顯不確定內容，或僅有空白網格   | 保留完整表格影像與框線                 |
| 照片、圖章、裝飾及需連同標籤保存的圖表             | 保留圖片與原稿位置關係                 |
| 無法安全分離圖文的複雜掃描頁                       | 保留頁面影像，僅替換通過檢查的完整段落 |
| 沒有能可靠重建的文字段落                           | 完整保留原稿頁面影像                   |

段落依行距、字級、縮排、條款編號與分隔線判定，OCR 提供的段落識別只作為參考。同一段中有不確定行時，整段會保留原圖，避免可編輯文字與圖片逐行交錯；其他獨立且可靠的段落仍可編輯。

照片跨越多個辨識區塊、無法安全分離時，系統會保留原稿構圖，只替換通過完整段落與字型外觀檢查的文字。若沒有段落通過，整頁只保留一次，避免重複圖片。

一般掃描頁的替代字型用來改善外觀，不會僅因缺少原稿字型就整頁轉為圖片。所有以圖片保留的文字均無法直接編輯。

## 版面與物件重建

### 文字、段落與分欄

依文字座標重建行、段落、首行縮排、懸掛縮排、段距、對齊及來源換行，保留可辨識的明確空白與定位點。原生文字可保留粗體、斜體、RGB 色彩、底線及上／下標基線位移，並處理部分字型名稱與字元映射。

清單使用 Word 原生編號與縮排，小數不直接視為清單編號。正文使用原生段落，不以逐行獨立文字方塊輸出。

分欄支援簡單雙欄、不等欄寬及跨欄元素，依位置推斷閱讀順序並建立 Word 分欄與分節。表單左右欄位會與正文雙欄分開判斷；確定欄界後，重新拆分誤接在同一行的文字片段。

### 字型與字寬

依裝置可用字型選擇替代字型，分開量測中西文字寬，在段落與儲存格內校準水平字寬並保留字級，避免為填滿空白而拉寬文字。

輸出會關閉 Word 自動中西文間距。保留來源換行時，接近滿行的原生中英數混排行可依文字交界預留最多 8% 的水平餘量，減少其他閱讀器額外插入間距造成的換行；Word 的 `fitText` 仍保留來源行寬。短行不套用此餘量，字級維持原樣。

### 表格與線條

向量線與掃描長線使用同一套網格分析，重建至少 2 × 2 的有框線表格。可重建的屬性包含欄寬、列高、矩形的水平／垂直合併儲存格、底色、框線、內距與垂直對齊。

薄填色矩形可轉為框線，鄰近雙框線採中央位置。跨越欄界的文字片段依字元寬度與空白間隙拆回儲存格，表內保留來源換行與字寬。部分僅有水平線的數字表格，可在欄位對齊及表頭／底線證據充分時重建；一般無框線表格尚未完整支援。

線條依用途分配：表格框線由表格處理，貼近文字基線的底線轉為文字樣式，其餘水平分隔線以段落框線輸出。保留為圖片的掃描表格會包含完整框線，避免與重建線條重複疊加。

### 圖片、圖表與裝飾

圖片依可見內容與版面關係處理，保留原稿構圖並減少重複內容：

- **獨立圖片**：單獨擷取照片、標誌、圖章與裝飾，避免將附近正文一起轉為圖片。重疊分片與相接圖片磚先依可見範圍合併。
- **局部圖文**：標誌、簽章提示等圖片可連同內部文字保留一次；與既有裁圖重疊時合併範圍，移除重複 OCR 文字與框線，附近正文仍可編輯。
- **圖表與標題帶**：有完整外框、圖形與數值標籤的圖表可整體保留。彩色標題帶即使沒有 OCR 文字，也保留底色與字形。
- **並排與環繞**：並排圖片使用單列無框線表格排列；與原生表格並排、同高度且無正文穿過的獨立圖片，依頁面位置錨定。簡單側邊圖片可錨定於段落並使用 Word 圖文環繞。
- **圖章與浮水印**：可使用頁面錨定保留位置；符合條件的紅色圖章可移除白底，普通圖片保留原背景。
- **複合圖層**：點陣圖片與向量裝飾交錯時，可組成不含正文的圖像層以保留遮擋順序。頁尾圖像另錨定於 Word 頁尾。

圖片維持比例，只縮小、不放大，並限制在可用頁高內。難辨識區塊的裁圖依來源位置與高度配置，避免圖片基線或固定行高造成多餘空白與內容裁切。

### 公式與頁尾

以分數線、上下位置與同基線運算符辨識簡單分數，輸出可編輯的 Word 公式；普通底線不作為分數依據。

可確定的底部數字與重複原生頁尾文字，可輸出至 Word 頁尾。目前頁碼使用 `PAGE` 欄位，來源總頁數文字保持原樣。

### 紙張、邊界與分頁

自動讀取 PDF 實際尺寸與方向，優先匹配 A4、A3、A5、Letter，容許約 1% 或 3 pt 的尺寸誤差；不吻合時保留原稿尺寸。長邊超過 22 吋的掃描頁，會等比例縮至長邊 29.7 公分，文字座標、字級與圖像同步縮放。

邊界依同尺寸、同方向頁面的正文、表格、分欄及圖文位置共同推估，以常見設定為優先候選：

| 邊界類型 | 上／下    | 左／右    |
| -------- | --------- | --------- |
| 窄邊界   | 1.27 公分 | 1.27 公分 |
| 標準邊界 | 2.54 公分 | 3.18 公分 |

短行與未寫滿的頁面不直接作為右／下邊界證據；稀疏頁可沿用同組正文頁的判斷。證據不足時採常見邊界，有明確非典型內容範圍時保留推估值。這些設定來自 PDF 幾何位置推估，無法直接取回原 Word 的頁面設定。

輸出依紙張座標安排留白、欄寬、字級與來源分頁，不將內容範圍拉伸至邊界，也不以裁字或縮小字級強行對頁。

## 資料保護與資源限制

### 資料處理範圍

- 原始 PDF、擷取文字、頁面影像與 DOCX 都在瀏覽器中處理，文件內容不會上傳至伺服器。
- OCR 使用 Tesseract.js，Worker、WASM 與繁體中文／英文模型由本站靜態資源提供，不使用遠端 OCR 或雲端語言模型。
- 首次辨識需下載程式與模型；瀏覽器可能快取模型，但文件內容不會寫入持久儲存。
- 重新整理或關閉頁面後，處理狀態不會保留，完成後需自行下載並保存結果。

### 處理上限

| 項目                | 限制                                                  |
| ------------------- | ----------------------------------------------------- |
| 輸入文件            | 一份 PDF，最多 32 MB、600 頁                          |
| 處理範圍            | 所選頁面，預設全選                                    |
| OCR Worker 生命週期 | 每處理 10 頁自動釋放並重建                            |
| 單頁文字片段        | 最多 25,000 個                                        |
| 單頁繪圖操作        | 最多 100,000 個                                       |
| 單頁表格候選線      | 最多 2,000 條                                         |
| 單次轉換版面物件    | 文字片段、線條及填色合計最多 250,000 個               |
| 單次轉換保留圖片    | 總量最多 32 MB                                        |
| OCR 畫布            | 最多 800 萬像素，單邊最多 4,096 像素                  |
| OCR 解析度          | 一般頁面約 216 DPI，特殊尺寸依畫布限制縮小            |
| 逾時保護            | 每頁 OCR、每次版面 Worker 與輸出 Worker 作業各 2 分鐘 |

Word 轉換的單檔大小限制為 32 MB，選取較少頁面不會提高此上限。所選頁面共用版面資訊與資源預算；超限時會停止處理，不會只輸出部分頁面。較大或結構密集的文件，需先拆分後再分別轉換。

## 已知限制

| 類別           | 說明                                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 辨識可靠程度   | OCR 可能產生錯字、數字或全半形標點差異，高信心仍可能辨識錯誤。字元數、片段覆蓋、辨識信心與頁數均不能代表內容正確率或完整還原程度。 |
| 可編輯範圍     | 原圖區塊與整頁影像中的文字無法直接編輯；自動流程不會辨識每張局部圖片中的文字。向量裝飾保留為圖像，不會轉成原生 Word 圖形。         |
| 字型與外觀     | 不嵌入原 PDF 字型，依裝置可用字型替代。掃描字型、粗體與色彩尚無法全面可靠重建；圖片保留效果也受來源渲染器影響。                    |
| 複雜結構       | 一般直排／旋轉文字、RTL、複雜公式、一般無框線表格、跨頁表格、三欄以上及完整頁首頁尾語意尚未完整支援。                              |
| 掃描表格與圖文 | 淡色或破碎框線、合併儲存格、貼線字形及密集圖文仍可能誤判或分離不全，無法可靠重建的區域會保留原圖。                                 |
| 圖文環繞       | 目前限於同一書寫區域中、頂端相近且左右不重疊的單張圖片與正文；多圖環繞、跨欄圖形及複雜遮罩仍有重建限制。                           |
| 分頁與編輯     | Word 與 LibreOffice 的字型度量及浮動圖形處理可能造成不同換行與分頁。原生段落與表格也會隨編輯重新流動，無法保證與原稿維持相同版面。 |
| 裝置效能       | 大型或複雜文件仍受瀏覽器記憶體與裝置效能影響，行動裝置可能較早遇到資源限制。                                                       |

下載後應對照原稿核對文字、數字、表格、圖像與分頁，尤其是 OCR 內容及介面提示需核對的頁面。

## 技術架構

核心以 TypeScript 實作，使用 PDF.js 讀取 PDF、Tesseract.js 執行本機 OCR，再由 `docx` 產生 OOXML 文件。

```text
File / ArrayBuffer + 所選頁碼
  → PDF.js：文字、字型、繪圖路徑與圖片位置
  → 必要時執行本機 OCR：掃描校正、文字／儲存格重辨識
  → RawPage：文字片段、座標、線段、填色、圖片與來源資訊
  → 物件分類與歸屬：正文、表格、線條、圖片、公式、頁尾
  → Layout Worker：文字行、段落、閱讀順序與分欄
  → DocumentModel：頁面、段落、清單、表格與診斷資訊
  → Export Worker：DOCX / OOXML 打包
  → Blob / 本機下載
```

版面分析與 DOCX 打包使用獨立 Worker，支援取消、逾時及錯誤處理。OCR 模型載入期間取消時，尚未完成初始化的 Worker 會在初始化完成後釋放。

文件模型保留來源頁碼、文字片段識別碼與診斷資訊。來源片段未完整涵蓋、存在阻擋錯誤，或沒有可輸出的文字與圖片時，會阻止下載。

### 主要程式位置

介面入口為 `src/features/convert/PdfConversionWorkspace.tsx`，負責共用的文件匯入、頁面選取與原稿預覽。下表除 `vite.config.ts` 外，皆以 `src/features/pdf2docx/` 為起點。

| 程式位置                                                                                    | 職責                                                         |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `WordOutput.tsx`                                                                            | Word 掃描操作、處理進度、結果摘要與下載                      |
| `types.ts`                                                                                  | 來源資料、文件模型與診斷型別                                 |
| `lib/analyzePdf.ts`、`lib/limits.ts`                                                        | 所選頁面處理、OCR 批次生命週期與資源限制                     |
| `lib/extractPage.ts`、`lib/framedGraphics.ts`                                               | PDF 內容讀取、頁面渲染、圖片與完整圖表擷取                   |
| `lib/ocr.ts`、`lib/ocrLayout.ts`、`lib/ocrGeometry.ts`                                      | 本機模型、語言／橫向重試、字框、基線與字級處理               |
| `lib/ocrLines.ts`、`lib/ocrTables.ts`、`lib/ocrConsensus.ts`                                | 文字行與儲存格重辨識、候選結果比較                           |

### PDF.js 圖層擷取相容性

`getOperatorList()` 回傳的操作清單與 `render()` 執行時的最佳化清單不同，不能直接共用操作索引。圖層擷取需依渲染時的操作清單及繪製順序選取內容，相關相容處理集中於 `lib/extractPage.ts`。

這項處理依賴 PDF.js 的內部渲染介面。升級依賴時需確認介面仍相容；無法安全擷取時明確失敗，避免靜默遺漏內容或將正文重複繪入圖片。

## 後續方向

公開樣本、已驗證的修正、剩餘版面問題與重現指令，請見 [PDF2DOCX-QA.md](PDF2DOCX-QA.md)。目前 corpus 包含 21 份、91 個選取頁面；內容測試與實際 Word 渲染分開評估。

- 擴充無框線表格、跨頁表格、清單層級、三欄以上及頁首頁尾的結構重建。

- 提升主流瀏覽器與行動裝置的資源使用效率。
