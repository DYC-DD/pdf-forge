# PDF 轉 Word（PDF2docx）

PDF2docx 是 PDF Forge「04 轉換 PDF」中的 **Word beta** 功能，入口為 `/convert/`；舊的 `/pdf2docx/` 連結會導向轉換工具。它在瀏覽器讀取所選 PDF 頁面，將能重建的文字、段落與表格輸出為可編輯的 Word 內容，並以圖片保留難以可靠重建的區域，最後產生一份 DOCX。

轉換仍在開發中。結果會受原稿結構、字型、辨識品質和 Word 等閱讀器影響；即使頁數相同，也不代表文字、順序與版面完全一致。下載後請對照原稿，特別核對文字、數字、表格、公式、勾選框與需審閱的頁面。

## 使用流程

1. 在「04 轉換 PDF」加入一份 PDF，選擇 **Word beta**。
2. 選取要轉換的頁面；可使用縮圖或頁碼範圍，例如 `1-3, 5, 8`。預設選取全部頁面。
3. 執行「掃描文件內容」。系統讀取文字與版面，必要時自動執行 OCR。更換文件或頁面後需重新掃描。
4. 檢視掃描摘要，下載 DOCX。所選頁面依原稿順序輸出，檔名可修改。

摘要顯示可編輯字元數、Word 表格數及需核對的頁數；保留在圖片中的文字不計入可編輯字元。未選頁面時不能掃描，掃描未完成或頁面讀取失敗時不能下載。處理期間可取消，逾時或超過資源限制時會顯示原因。

## 內容辨識與輸出

### 原生文字與 OCR

有可用文字層時，系統優先讀取文字、座標、字型、字級、色彩及繪圖資訊，推斷閱讀順序與結構。PDF 中不可見的搜尋文字不直接當作可見正文；被後繪製的不透明矩形完整遮住的文字也不納入輸出。

掃描頁、異常字元映射或無法直接讀取的可見內容，可能進入本機 OCR。辨識以繁體中文模型為主；英文主導的頁面可依辨識結果重試英文模型，後續頁面恢復主要模型。處理包含傾斜校正、表格線偵測，以及文字行和儲存格的有限次局部重辨識。預處理只作用於辨識輸入，不改動原始 PDF。

部分原生表格只有局部字元映射異常時，若區域及可保留的文字符合條件，可只保留缺碼儲存格的原圖，其他可靠文字仍可編輯，並顯示審閱提示。範圍過大、跨格或無法安全隔離時，仍依情況進入 OCR 或錯誤處理。

### 可編輯文字與原稿影像

| 內容狀況                                     | 輸出方式               |
| -------------------------------------------- | ---------------------- |
| 能可靠重建的文字、清單                       | 原生 Word 段落與清單   |
| 能可靠重建的網格與內容                       | 原生 Word 表格         |
| 浮水印重疊、低信心或容易受底線干擾的掃描段落 | 保留完整段落的原稿裁圖 |
| 無法可靠辨識的表格內容或空白網格             | 保留表格影像與框線     |
| 無法安全分離的複雜圖文，或沒有可靠段落的頁面 | 保留局部或整頁原稿影像 |

掃描段落依行距、字級、縮排、編號及分隔線等資訊判定；同一段有不確定內容時，可能整段保留原圖，其他可靠段落仍可編輯。搜尋文字層與新 OCR 結果有歧異時，也可能保留原圖，避免將不確定內容當作正確文字。

局部圖片與整頁影像中的文字無法直接編輯；可編輯字元數及 OCR 信心都不能保證文字正確。替代字型可改善掃描文字的外觀，但仍需核對內容。

## 版面與物件重建

### 文字、清單與分欄

系統依位置推斷行、段落、縮排、對齊、段距及來源換行，並盡可能保留粗體、斜體、色彩、底線及上／下標位置。清單使用 Word 原生編號和縮排；點狀導引線及部分填空底線可保留在原行。

分欄依欄界及文字位置推斷閱讀順序，支援簡單雙欄、不等欄寬及部分三欄與跨欄標題案例。表單欄位會與正文分欄分開判斷。複雜欄序、跨欄內容與不規則表單仍可能錯位或交錯，不能因個別多欄樣本通過而視為全面支援。

部分首字下沉、文字定位點及左右分置標題可重建，但字距、續行與較複雜的版型仍可能不同。一般旋轉文字及雙向混排尚未完整支援。

### 字型與文字外觀

輸出不嵌入原 PDF 字型；系統依裝置可用字型選擇替代字型，量測中西文字寬並校準部分文字與儲存格，盡量保留原字級。Word 自動中西文間距會關閉；部分接近滿行的原生混排行保留有限的水平餘量，以減少閱讀器換行差異。

PDF 的底線、背景填色與分隔線會依位置和外觀分類；部分文字標示帶可保留原色。彩色、多重或虛線底線仍可能與文字錯位。特殊字型可能被替代，例如條碼字型目前可能失去可掃描的圖形外觀。

### 表格、表單與線條

向量線與掃描長線可用於分析有框線網格，重建欄寬、列高、部分合併儲存格、底色、框線、內距及垂直對齊。符合條件的水平線數字表格也可重建；一般無框線表格及複雜跨頁表格仍有限制。部分 90°／−90° 表格文字可使用 Word 原生儲存格文字方向保留可編輯性。

勾選框等小型控制項可保留局部外觀，明確符合條件者會相對鄰近文字定位；不適合安全錨定的情況保留原有處理。這不代表 Word 輸出是可互動表單，也不能保證不規則網格、側邊標籤及簽署區對齊。

表格框線、文字底線與其他分隔線分開處理；無法可靠重建的表格可保留影像，避免遺失內容。淡色、破碎或不規則框線仍可能遺失或誤判。

### 圖片、圖表與公式

照片、標誌、圖章及裝飾可獨立擷取；相關文字與圖形難以安全分離時，可一併保留為局部圖片。部分圖表、流程圖、彩色標題帶及圖層交錯的裝飾會保留構圖；周圍可靠的正文仍可編輯。簡單側邊圖片支援有限的圖文環繞，並排圖片可使用無框線表格排列。

簡單分數可輸出為可編輯的 Word 公式。複雜公式的矩陣、大型運算子及上下標位置可能不正確，需逐項核對；不能僅憑文字可編輯就認為數學語意正確。

### 紙張、邊界與分頁

系統讀取 PDF 實際尺寸與方向，優先匹配常見的 A4、A3、A5 及 Letter；不吻合時保留自訂尺寸。長邊超過 22 吋的掃描頁會等比例縮小，文字與圖片座標同步調整。

頁面邊界由同尺寸、同方向頁面的正文、表格、分欄及圖文位置推估，並非取回原 Word 的頁面設定。輸出盡量依來源座標與分頁安排內容，但字型替代、浮動圖片、表格行高及後續編輯都可能改變換行與分頁。可確定的重複頁尾及底部頁碼可輸出到 Word 頁尾；目前頁碼使用 `PAGE` 欄位，來源總頁數文字保持原樣。

| 圖表與資訊圖       | 統計長圖、人口金字塔及漸層資訊圖仍可能出現多餘分頁、背景、標籤或圖例錯位。                                                       |

改善方向包括表單分區與行高、文字與底線保真、複雜文字及直排辨識、公式語意、圖表圖層、跨頁表格，以及不同閱讀器的分頁。修正時應保留既有內容與品質門檻，不以減少文字、縮小字級或整頁圖片化掩蓋失敗。

## 驗證與品質紀錄

### 驗證範圍

公開樣本包含原生文字、掃描、清單、表格、多欄、表單、多語文字、公式、圖表及不同紙張尺寸。樣本來源、選取頁碼、SHA-256 與各自條件記錄在 [`pdf2docx-public.json`](../src/tests/__fixtures__/pdf2docx-public.json) 及 [`pdf2docx-expanded.json`](../src/tests/__fixtures__/pdf2docx-expanded.json)。下載器會驗證來源及快取雜湊；不符時停止，需先核對原稿。

驗證分為幾個獨立面向：

- **單元與回歸測試**：檢查版面分析、OCR、物件歸屬及 DOCX 輸出等行為。
- **內容與結構**：依樣本要求檢查來源文字、可編輯字元、閱讀順序、表格、圖片或其他指定條件。
- **實際渲染**：用 Word 開啟 DOCX 並輸出 PDF，再核對頁數、指定表格數與適用的文字、控制項或背景定位。
- **人工比對**：對照來源與渲染結果，檢查自動門檻未涵蓋的字形、公式、圖表及整體版面。

頁數、字元數或部分錨點通過，只能證明對應條件成立。需分別確認文字完整性、可編輯性、語意、座標及視覺外觀。

### 重現方式

以下在專案根目錄的 Windows PowerShell 執行；Word 渲染需要安裝 Microsoft Word。Node.js 與 npm 版本依 `package.json` 指定。下載公開樣本需要網路；後續轉換、OCR 與驗證在本機執行。

```powershell
npm ci
node --use-system-ca scripts/pdf2docx-public.mjs download
node --use-system-ca scripts/pdf2docx-public.mjs download --expanded
npm test
npm run build
```

先產生 public 樣本的 DOCX 和診斷資料，再執行實際 Word 渲染及檢查：

```powershell
$env:PDF2DOCX_QA_DIR = '.cache/pdf2docx-public/verification'
node scripts/pdf2docx-public.mjs test
./scripts/verify-pdf2docx-word.ps1 -Directory $env:PDF2DOCX_QA_DIR
$env:PDF2DOCX_CORPUS_MANIFEST = '.cache/pdf2docx-public/test-manifest.json'
node scripts/pdf2docx-check-rendered.mjs
```

擴充樣本使用獨立目錄與 manifest：

```powershell
$env:PDF2DOCX_QA_DIR = '.cache/pdf2docx-expanded/verification'
node scripts/pdf2docx-public.mjs test --expanded
./scripts/verify-pdf2docx-word.ps1 -Directory $env:PDF2DOCX_QA_DIR -Manifest .cache/pdf2docx-expanded/test-manifest.json
$env:PDF2DOCX_CORPUS_MANIFEST = '.cache/pdf2docx-expanded/test-manifest.json'
node scripts/pdf2docx-check-rendered.mjs
Remove-Item Env:PDF2DOCX_CORPUS_MANIFEST
Remove-Item Env:PDF2DOCX_QA_DIR
```

內容測試可能因已知品質門檻失敗；應保留失敗結果與產生的診斷檔，確認所需 DOCX 均存在後，再分別執行渲染與檢查。Word 腳本使用獨立的隱藏 Word 執行個體，匯出 PDF 和 `word-pagination.json`；渲染檔不存在、頁數或指定表格數不符時會報錯。渲染檢查依 manifest 比對實際 PDF，失敗時回傳非零狀態。自動檢查後仍需目視核對；其他 Word 版本、LibreOffice 和瀏覽器需另行驗證。

## 資料保護與資源限制

原始 PDF、擷取文字、頁面影像及 DOCX 在瀏覽器處理，文件內容不會上傳至伺服器。OCR 使用 Tesseract.js，Worker、WASM 及繁中／英文模型由本站靜態資源提供；首次辨識需要下載程式與模型，瀏覽器可能快取模型，但文件內容不寫入持久儲存。重新整理或關閉頁面後不保留處理狀態，完成後需自行下載。

| 項目                               | 限制                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------ |
| 輸入                               | 一份 PDF，最多 32 MB、600 頁                                             |
| OCR Worker                         | 每處理 10 頁自動釋放並重建；並非每次只能處理 10 頁                       |
| 單頁文字片段／繪圖操作／表格候選線 | 最多 25,000 個／100,000 個／2,000 條                                     |
| 單次轉換版面物件                   | 文字片段、線條及填色合計最多 250,000 個                                  |
| 單次轉換保留圖片                   | 總量最多 32 MB                                                           |
| OCR 畫布                           | 最多 800 萬像素，單邊最多 4,096 像素；一般約 216 DPI，特殊尺寸依限制縮小 |
| 逾時                               | 每頁 OCR、每次版面 Worker 與輸出 Worker 作業各 2 分鐘                    |

所選頁面共用版面資訊與資源預算。超限時會停止處理，不會只輸出部分頁面；大型或結構密集的文件可先拆分後分別轉換。

## 技術架構

核心以 TypeScript 實作，使用 PDF.js 讀取 PDF、Tesseract.js 執行本機 OCR，再由 `docx` 產生 OOXML：

```text
PDF + 所選頁碼
  → PDF.js 擷取文字、字型、路徑及圖片；必要時執行 OCR
  → RawPage：文字片段、座標、線段、填色、圖片及來源資訊
  → 物件分類：正文、表格、線條、圖片、公式及頁尾
  → Layout Worker：文字行、段落、閱讀順序與分欄
  → DocumentModel：頁面、段落、清單、表格及診斷資訊
  → Export Worker：DOCX / OOXML 打包
  → 瀏覽器下載
```

版面分析與 DOCX 打包使用獨立 Worker，支援取消、逾時及錯誤處理。來源片段未完整涵蓋、存在阻擋錯誤，或沒有可輸出的文字與圖片時會阻止下載。

| 主要位置                                                                          | 職責                              |
| --------------------------------------------------------------------------------- | --------------------------------- |
| `src/features/convert/PdfConversionWorkspace.tsx`                                 | 文件匯入、頁面選取及原稿預覽      |
| `src/features/pdf2docx/WordOutput.tsx`、`types.ts`                                | Word 操作介面、文件模型及診斷型別 |
| `lib/analyzePdf.ts`、`limits.ts`、`extractPage.ts`                                | 所選頁面處理、資源限制與 PDF 擷取 |
| `lib/ocr*.ts`、`scan*.ts`、`editableScan.ts`                                      | 本機 OCR、掃描預處理及可編輯範圍  |
| `lib/pageObjects.ts`、`textAppearance.ts`、`textBackgrounds.ts`                   | 物件歸屬、文字與背景外觀          |
| `lib/geometry.ts`、`paragraphs.ts`、`layout.ts`、`sideHeadings.ts`、`dropCaps.ts` | 幾何、段落、欄序及部分特殊版面    |
| `lib/tables.ts`、`openTables.ts`、`formControls.ts`、`fractions.ts`               | 表格、表單控制項及簡單分數        |
| `lib/pageSetup.ts`、`fontMetrics.ts`                                              | 紙張、邊界、座標及字型度量        |
| `lib/runDocxJob.ts`、`docx.worker.ts`、`exportDocx.ts`                            | Worker 通訊及 Word 內容輸出       |
| `vite.config.ts`                                                                  | 複製 OCR 靜態資源與部署路徑處理   |

除特別標示外，表中的 `lib/` 路徑均位於 `src/features/pdf2docx/`。

PDF.js 的 `getOperatorList()` 與 `render()` 使用的最佳化操作清單不同，不能直接共用操作索引。圖層擷取依渲染時的操作清單與繪製順序處理；由於涉及 PDF.js 內部介面，升級依賴時應重新驗證，無法安全擷取時明確失敗，避免靜默遺漏或重複繪製內容。
