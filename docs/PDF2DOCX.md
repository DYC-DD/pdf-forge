# PDF2docx 功能與技術說明

PDF2docx 是 PDF Forge 的獨立開發預覽功能，入口為 `/pdf2docx/`。它在瀏覽器中讀取 PDF，將可重建的文字、段落與表格轉成可編輯的 Word 內容，並以圖片保留圖像及難以可靠辨識的區塊，最後輸出一份 DOCX。

此功能與既有的「04 轉換 PDF」分開開發。轉換以保留內容、可編輯結構與原稿版面為目標，仍不保證所有 PDF 都能完整還原，或所有區塊都能直接編輯。

## 使用方式

1. **加入 PDF**：一次加入一份文件，介面提供原稿預覽。
2. **選擇頁面**：預設全選，可點選頁面縮圖或輸入頁碼範圍（例如 `1-3, 5, 8`）後套用；支援全選、清除、列表與網格顯示。
3. **掃描文件內容**：只處理所選頁面，優先讀取原生文字，必要時執行本機 OCR，並分析段落、表格、圖片與版面。變更選取後需重新掃描。
4. **下載 Word**：所選頁面依原稿順序輸出成一份 DOCX，沿用原檔名並將副檔名改為 `.docx`。

使用者無須設定 OCR 模式、辨識語言、紙張、邊界或分頁方式。未選取頁面時無法掃描或下載。處理期間可取消；遇到讀取失敗、逾時或資源超限時，介面會顯示原因。

掃描完成後，輸出區會顯示可編輯字元數、Word 表格數及需核對的頁數。保留為圖片的文字不計入可編輯字元數；下載後請對照原稿核對內容與排版。

## 本機處理與資料保護

- 原始 PDF、擷取文字、頁面影像與產生的 DOCX 都在瀏覽器中處理，文件內容不會上傳至伺服器。
- OCR 使用 Tesseract.js；Worker、WASM 與繁體中文／英文模型由本站靜態資源提供，不使用遠端 OCR 或雲端語言模型。
- 首次辨識需要下載程式與語言模型。瀏覽器可能快取模型，但文件內容不會寫入持久儲存。
- 重新整理或關閉頁面後，處理狀態不會保留，完成後需自行下載並保存結果。

## 轉換策略

### 原生文字優先

有可用文字層的 PDF 會直接讀取文字、座標、字型、字級、色彩與繪圖資訊，再推斷閱讀順序及文件結構。正文輸出為 Word 原生段落，清單使用編號定義，表格使用原生儲存格。

每個可見文字片段只歸屬正文、表格、公式或頁尾其中一處，避免重複輸出。被後繪製的不透明矩形完整遮住的文字不會納入結果；透明填色不作為刪除文字的依據。

### 必要時自動辨識

整頁掃描、異常字元映射、無文字層的向量內容，或包含無法直接讀取的可見表單值時，系統會自動執行 OCR。留有頁邊的地圖等獨立圖片頁可直接保留為圖片。

辨識以繁體中文模型為主，英文主導的頁面會視結果使用英文模型重試。密集的橫向繁中正文可另以單區塊模式辨識，只有文字量、相似度與辨識信心符合條件時才採用重試結果；後續頁面恢復主要辨識模式。

OCR 會保留區塊與段落識別，搭配傾斜校正、表格線偵測、字框與基線修正，以及字級估算，減少文字與框線互相干擾。表格線只從辨識輸入中移除，原始文件不受修改。

### 依區塊決定可編輯性

掃描頁先重建文字與表格，再依內容可靠程度選擇輸出形式：

| 內容狀況                                                     | 輸出方式                   |
| ------------------------------------------------------------ | -------------------------- |
| 能可靠重建的正文                                             | 可編輯的 Word 段落與清單   |
| 網格與文字均能可靠重建的表格                                 | 原生 Word 表格             |
| 浮水印與文字重疊的完整文字行、低信心內容、易受底線干擾的數字 | 保留原稿裁圖               |
| 儲存格重辨識後仍有明顯不確定內容的表格                       | 保留完整表格影像與框線     |
| 照片、圖章、裝飾及其他圖像                                   | 保留圖片，依版面配置位置   |
| 無法可靠重建文字的掃描頁                                     | 保留原稿頁面影像並顯示提示 |

局部重辨識使用加白邊的裁圖與有限次去雜訊，逐字比較候選結果，保護已清楚讀取的數字。主要辨識保留原稿字形，避免移除浮水印時一併擦除正文。難辨識區塊以原圖保留，相鄰可靠正文仍可編輯。

替代字型用來改善文字外觀；缺少原稿字型不會直接導致整頁轉為圖片。圖片中的文字無法直接編輯，介面會提供相關提示。

## 內容與版面重建

### 文字、段落與清單

- 依文字座標重建行、段落、首行縮排、懸掛縮排、段距、對齊及來源換行，保留可辨識的明確空白與定位點。
- 讀取原生文字的粗體、斜體、RGB 色彩、底線及上／下標基線位移，並處理部分字型名稱與字元映射。
- 清單使用 Word 原生編號與縮排；小數不直接視為清單編號，續行保留相應對齊關係。
- 偵測裝置可用的替代字型，分開量測中西文字寬，在段落與儲存格內校準水平字寬並保留字級，避免為填滿空白而拉寬文字。
- 關閉 Word 自動中西文間距，減少額外空白造成的換行差異。正文不以逐行獨立文字方塊輸出。

### 閱讀順序與分欄

支援簡單雙欄、不等欄寬及跨欄元素，依內容位置推斷閱讀順序，輸出 Word 分欄與分節。表單左右欄位會與正文雙欄分開判斷；確定欄界後，重新分開被接成同一行的文字片段。

### 表格與線條

向量線與掃描長線使用同一套網格分析，重建至少 2 × 2 的有框線表格，支援欄寬、列高、矩形的水平／垂直合併儲存格、底色、框線、內距與垂直對齊。

薄填色矩形可轉為框線，鄰近的雙框線採中央位置。跨越欄界的文字片段會依字元寬度與空白間隙拆回儲存格，表內保留來源換行與字寬。部分只有水平線的數字表格，可在欄位對齊及表頭／底線證據充分時重建；一般無框線表格尚未完整支援。

線條先依用途分配：表格框線由表格處理，貼近文字基線的底線轉為文字樣式，其餘水平分隔線以段落框線輸出。掃描表格會先重辨識儲存格；無法可靠重建或只有空白網格時，保留原稿影像與完整框線。

### 圖片、圖章與浮水印

- 可分離的圖片單獨擷取，避免把附近正文一起轉為圖片；大型照片、向量裝飾與可判定的浮水印也會保留。
- 重疊圖片分片與相接的圖片磚，先依可見範圍合併，避免重複輸出或分片散落。
- 並排圖片使用單列無框線表格排列；簡單側邊圖片可錨定於段落，使用 Word 圖文環繞。
- 圖章、頁邊圖像與斜向浮水印可使用頁面錨定。符合條件的紅色圖章可移除白底，普通圖片保留原背景。
- 點陣圖片與向量裝飾交錯的頁面，可組成不含正文的圖像層以保留遮擋順序；頁尾圖像另錨定於 Word 頁尾。
- 圖片維持比例，只縮小、不放大，並限制在可用頁高內。難辨識區塊的裁圖依來源位置與高度配置，避免圖片基線或固定行高造成多餘空白與內容裁切。

### 公式與頁尾

以分數線、上下位置與同基線運算符辨識簡單分數，輸出可編輯的 Word 公式；普通底線不作為分數依據。

可確定的底部數字及重複原生頁尾文字可輸出至 Word 頁尾。目前頁碼使用 `PAGE` 欄位，來源總頁數文字保持原樣。完整頁首頁尾語意與複雜公式仍有重建限制。

### 紙張、邊界與分頁

自動讀取 PDF 實際尺寸與方向，優先匹配 A4、A3、A5、Letter，容許約 1% 或 3 pt 的尺寸誤差；不吻合時保留原稿尺寸。長邊超過 22 吋的掃描頁會等比例縮至長邊 29.7 公分，文字座標、字級與圖像同步縮放。

邊界依同尺寸、同方向頁面的正文、表格、分欄及圖文位置共同推估，以常見設定作為優先候選：

- **窄邊界**：四邊 1.27 公分。
- **標準邊界**：上下 2.54 公分、左右 3.18 公分。

短行與未寫滿的頁面不直接作為右／下邊界證據；稀疏頁可沿用同組正文頁的判斷。證據不足時採常見邊界，有明確非典型內容範圍時保留推估值。這是依 PDF 幾何位置推估，無法直接取回原 Word 的頁面設定。

輸出依紙張座標保留留白、欄寬、字級與來源分頁，不將內容範圍拉伸至邊界，也不以裁字或縮小字級強行對頁。Word 仍會依可用字型及後續編輯重新排版，因此實際分頁可能與原稿不同。

## 處理架構

核心以 TypeScript 實作，使用 PDF.js 讀取 PDF、Tesseract.js 執行本機 OCR，再由 `docx` 產生 OOXML 文件。

```text
File / ArrayBuffer
  → PDF.js：文字、字型、繪圖路徑與圖片位置
  → 必要時執行本機 OCR：傾斜校正、文字／儲存格重辨識
  → RawPage：文字片段、座標、線段、填色、圖片與來源資訊
  → 物件分類與歸屬：正文、表格、線條、圖片、公式、頁尾
  → Layout Worker：文字行、段落、閱讀順序與分欄
  → DocumentModel：頁面、段落、清單、表格與診斷資訊
  → Export Worker：DOCX / OOXML 打包
  → Blob / 本機下載
```

所選頁面共用版面資訊及資源預算。OCR Worker 每處理 10 頁會自動釋放並重建，最後仍輸出一份完整 DOCX。超過全文件資源限制時會停止處理，不會只輸出前幾頁。

版面分析與 DOCX 打包使用獨立 Worker，支援取消、逾時及錯誤處理。OCR 模型載入期間取消時，尚未完成初始化的 Worker 會在初始化完成後釋放。文件模型保留來源頁碼、文字片段識別碼及診斷資訊；來源片段未完整涵蓋、存在阻擋錯誤，或沒有可輸出的文字與圖片時，會阻止下載。

## 資源限制

| 項目           | 限制                                                  |
| -------------- | ----------------------------------------------------- |
| 輸入文件       | 一份 PDF，最多 32 MB、600 頁                          |
| 處理範圍       | 所選頁面，預設全選；OCR Worker 每 10 頁自動更新       |
| 單頁文字片段   | 最多 25,000 個                                        |
| 單頁繪圖操作   | 最多 100,000 個                                       |
| 單頁表格候選線 | 最多 2,000 條                                         |
| 全文件版面物件 | 文字片段、線條及填色合計最多 250,000 個               |
| 全文件保留圖片 | 總量最多 32 MB                                        |
| OCR 畫布       | 最多 800 萬像素，單邊最多 4,096 像素                  |
| OCR 解析度     | 一般頁面約 216 DPI，特殊尺寸依畫布限制縮小            |
| 逾時保護       | 每頁 OCR、每次版面 Worker 與輸出 Worker 作業各 2 分鐘 |

較大或結構密集的文件仍受瀏覽器記憶體與裝置效能影響。超過限制時，需先拆分文件再分別轉換。

## 已知限制

- **辨識可靠程度**：OCR 可能產生錯字、數字或全半形標點差異；高信心仍可能辨識錯誤。字元數、片段覆蓋與辨識信心都是診斷資訊，不能視為內容正確率，頁數相同也不代表完整還原。
- **字型與外觀**：不嵌入原 PDF 字型，依裝置可用字型替代。掃描字型、粗體與色彩尚無法全面可靠重建；Word 與 LibreOffice 的字型度量及浮動圖形處理可能造成不同換行與分頁。
- **複雜結構**：一般直排／旋轉文字、RTL、複雜公式、一般無框線表格、跨頁表格、三欄以上及完整頁首頁尾語意尚未完整支援。
- **掃描表格與圖文**：淡色或破碎框線、合併儲存格、貼線字形及密集圖文仍可能誤判或分離不全，無法可靠重建的區域會保留原圖。
- **圖片內文字**：自動流程不會辨識每張局部圖片中的文字；隨圖片保留的文字無法直接編輯。向量裝飾也以圖像保留，不會轉成可編輯的 Word 圖形。
- **圖文環繞**：目前限於同一書寫區域中、頂端相近且左右不重疊的單張圖片與正文；多圖環繞、跨欄圖形及複雜遮罩仍有重建限制。
- **編輯後排版**：原生段落與表格會隨文字修改重新流動；原稿分頁與位置資訊無法保證編輯後仍維持相同版面。

下載後應對照原稿核對文字、數字、表格與圖像範圍，尤其是 OCR 內容或介面提示有頁面需核對時。

## 後續方向

- 改善異常字元映射、低對比掃描、混合掃描區域及疑字定位，提升文字與數字辨識品質。
- 擴充無框線表格、跨頁表格、清單層級、三欄以上與頁首頁尾的結構重建。
- 持續改善字型替代、圖文環繞及編輯後的版面流動行為。
- 提升主流瀏覽器與行動裝置的資源使用效率，再評估與既有轉換流程整合。
